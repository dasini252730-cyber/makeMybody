## 목표
BaseTextField 가 autocomplete, name, enterkeyhint 등 입력 속성을 input 에 넘기지 않아(루트 div 로 감) 로그인 화면에서 브라우저·모바일 자동완성이 안 된다. inheritAttrs:false + v-bind="$attrs" 를 input 에 적용하거나 명시 prop 추가. LoginView 에 username/current-password 적용. T-007 리뷰 사소 항목.

## 배경 / 요구사항 참조
요구사항.md의 NFR-001, NFR-006 섹션을 참조한다.

## 작업 단계
1. BaseTextField: `defineOptions({ inheritAttrs: false })` + 루트가 아닌 `<input v-bind="$attrs">` 로 autocomplete/name/enterkeyhint 등을 전달 (class/style 은 루트에 유지할지 결정)
2. LoginView: 이메일 `autocomplete="username"`, 비밀번호 `autocomplete="current-password"`, `enterkeyhint="go"`
3. BaseTextField 테스트 추가: attrs 가 input 에 붙고 라벨/오류 연결은 그대로
4. DevUiView 사용처 확인

## 쉬운 설명

**한 줄 요약**: 로그인 화면에서 이메일·비밀번호 입력이 브라우저의 자동완성(저장된 계정)을 받도록 BaseTextField 컴포넌트를 개선합니다.

**왜 필요한가**: 현재 BaseTextField는 라벨, 타입, placeholder 등만 input에 전달하고, 자동완성을 활성화하는 `autocomplete`, `name`, `enterkeyhint` 속성들은 건너뜁니다(루트 div에 감싸져 있음). 이 속성들이 있으면 사용자가 저장된 로그인 정보를 빠르게 불러올 수 있어 접근성(NFR-006)과 사용성(NFR-001)이 향상됩니다.

**끝나면 보이는 것**:
- BaseTextField의 input 태그에 부모에서 전달한 모든 속성(autocomplete, name, enterkeyhint)이 도달
- LoginView 이메일 입력: 브라우저가 "사용자 이름 저장" 옵션 제안 및 자동 채우기
- LoginView 비밀번호 입력: 브라우저가 "비밀번호 저장" 옵션 제안 및 자동 채우기
- DevUiView 기존 사용처 동작 불변

**주의**:
- `inheritAttrs: false`를 추가하면 class/style 속성이 루트 div 대신 input으로 전달될 가능성이 있으므로, style 바인딩(`:class="{ invalid: !!error }"`)이 여전히 루트에 적용되는지 확인 필요
- T-007(LoginView)과 T-111(UI 접근성)이 이미 완료된 상태이므로, 기존 동작을 깨뜨리지 않는 것이 중요
