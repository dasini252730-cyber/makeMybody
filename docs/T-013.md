## 목표
세션과 세션 내 운동 테이블을 만든다.

## 배경 / 요구사항 참조
- **FR-002**: 운동 기록: 날짜, 운동 종류, 운동명, 세트, 반복, 중량, 시간, 거리, 난이도, 메모.
- **FR-003**: 복합운동 기록: 한 세션에 여러 운동을 개별 기록하되 하나의 Workout Session으로 묶음.
- **NFR-003**: 개인정보: Supabase RLS로 사용자별 접근 제한.

FR-002 예시:

```text
2026-10-07

Deadlift
40kg × 10
40kg × 10
50kg × 5

OHP
20kg × 20

Workout Duration
55분
```

## 작업 단계
1. workout_sessions(id, user_id, date, session_type(pt/solo/walk/hike), duration_min, rpe, title, created_at)
2. workout_exercises(id, session_id, exercise_id, order_no, note)
3. RLS 활성화 + `auth.uid() = user_id` 정책(select/insert/update/delete) (workout_exercises 는 session 조인으로 검사)
4. user_id+date 인덱스

## 완료 조건
- [ ] 타 사용자 세션의 exercises 조회 불가
- [ ] 세션 삭제 시 exercises cascade

## 결정 / 주의 사항
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**  
사용자가 운동한 세션(예: 어제 PT 수업)과 그 안의 운동들(스쿼트, 데드리프트 등)을 데이터베이스에 저장하는 테이블을 만든다.

**왜 필요한가**  
운동 기록(FR-002, FR-003)을 저장하려면 먼저 세션과 운동을 체계적으로 저장할 구조가 필요하다. 또한 다른 사용자의 운동 정보는 절대 볼 수 없도록 RLS 정책으로 보호해야 한다(NFR-003).

**끝나면 보이는 것**
- Supabase 대시보드의 데이터베이스에 workout_sessions, workout_exercises 두 테이블 생성됨
- 다른 사용자의 세션/운동 조회 불가능 (RLS로 보호됨)
- 세션 삭제 시 그 안의 모든 운동도 자동 삭제됨 (cascade)

**주의**  
선행 작업 T-011(profiles 테이블), T-012(exercise_library 테이블)이 완료되어야 이 작업을 시작할 수 있다. workout_exercises에서 exercise_id로 exercise_library를 참조하므로 T-012 완료가 필수다.
