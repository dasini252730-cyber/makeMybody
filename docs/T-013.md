## 목표

## 배경 / 요구사항 참조
- FR-001 세션 생성: 날짜 + 유형만으로 생성, raw_note 원문 메모(1.2)로 동작 없이도 저장.
- FR-002 운동 동작 및 세트: session_items에 exercise_id 참조, display_name_snapshot 저장.
- FR-005 기록 수정·삭제: soft delete (deleted_at), 6.3 클라이언트 UUID + upsert, updated_at 트리거.
- FR-020 통증 메모: session_items.pain_note 컬럼.
- 원본: 요구사항.md v1.2 (2026-10-11 개정). 아래 단계·조건은 v1.2 기준.
- 6.2 핵심 엔티티: workout_sessions 및 session_items 컬럼 정의.

## 작업 단계
1. workout_sessions(id uuid PK 클라이언트 생성, user_id, session_date, session_type CHECK, started_at, ended_at, duration_minutes, raw_note, structured_status CHECK none/partial/done default none, condition_note, general_note, source_type CHECK, created_at, updated_at, deleted_at)
2. session_items(id, session_id FK cascade, exercise_id nullable FK, display_name_snapshot, sequence_no, variation_note, assistance_note, difficulty_rpe CHECK 1~10, pain_note, item_note)
3. RLS: sessions 는 user_id = auth.uid(); items 는 EXISTS(세션 조인) 로 4개 정책
4. 인덱스: (user_id, session_date desc) WHERE deleted_at IS NULL; session_items(session_id, sequence_no)
5. updated_at 트리거

## 완료 조건
- [x] raw_note 만 있는 세션 insert 성공(items 0개)
- [x] 같은 id 로 upsert 두 번 → 행 1개
- [x] 타 사용자 세션의 items 조회 불가
- [x] 세션 삭제(deleted_at) 후에도 items 는 남고 조회에서 제외 가능

## 결정 / 주의 사항
- id 는 클라이언트 UUID(PK, default 없음). 서버 측 삽입도 id 를 명시해야 한다. 저장은 upsert(on conflict (id) do update).
- 삭제는 deleted_at. items 는 cascade 로 남아 있고, 목록·계산은 세션의 deleted_at IS NULL 로 걸러야 한다(repo 공통 필터, T-027/T-036).
- session_items.exercise_id 는 기본 운동 또는 세션 소유자 본인 운동만(트리거). FK 는 RLS 를 거치지 않기 때문.
- 검증: supabase/tests/rls_probe.sql 7번 블록 (npm run db:rls).

## 쉬운 설명

**한 줄 요약**  
사용자가 운동한 세션(예: 어제 PT 수업)과 그 안의 운동들(스쿼트, 데드리프트 등)을 데이터베이스에 저장하는 테이블을 만든다.

**왜 필요한가**  
운동 기록(FR-002, FR-003)을 저장하려면 먼저 세션과 운동을 체계적으로 저장할 구조가 필요하다. 또한 다른 사용자의 운동 정보는 절대 볼 수 없도록 RLS 정책으로 보호해야 한다(NFR-003).

**끝나면 보이는 것**
- Supabase 대시보드의 데이터베이스에 workout_sessions, session_items 두 테이블 생성됨
- RLS 정책으로 다른 사용자의 세션/동작 조회 불가능
- 세션의 soft delete (deleted_at) 이후에도 session_items 는 유지되고, 필터링으로 제외 가능

**주의**  
선행 작업 T-012(exercise_library 테이블)이 완료되어야 이 작업을 시작할 수 있다. session_items에서 exercise_id로 exercise_library를 참조하므로 T-012 완료가 필수다. 세션 soft delete 시 session_items 의 cascade 삭제는 데이터 정합성이 중요하다.
