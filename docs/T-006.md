## 목표
supabase/migrations 기반으로 스키마를 관리하는 절차를 만든다.

## 배경 / 요구사항 참조
- **TECH**: 기술: Vue 3 + Vite / Supabase(PostgreSQL, Auth, RLS, Storage, Edge Functions) / Vercel / AI는 추후 연동.

## 작업 단계
1. `npx supabase init` (완료), `supabase link --project-ref <기존 프로젝트 ref>`
2. link 직후 `npm run db:migrations` 로 원격에 다른 저장소의 마이그레이션 이력이 있는지 확인. 있으면 멈추고 보고(needs_decision).
3. init 마이그레이션 = `create schema mybody` + grant usage (작성 완료) → `npm run db:push`
4. 대시보드 Settings → API → Exposed schemas 에 `mybody` 추가 (수동, 사용자 또는 안내)
5. `npm run db:types` (--schema mybody) 로 타입 생성 확인

## 쉬운 설명

**한 줄 요약**  
Supabase CLI를 설정하고 데이터베이스 변경을 관리하는 마이그레이션 폴더 구조를 만든다.

**왜 필요한가**  
T-005에서 Supabase 프로젝트와 클라이언트를 연결했다면, 이제 그 안의 테이블을 만들고 변경할 때마다 추적할 방법이 필요하다. 마이그레이션 파일로 관리하면 팀과 로컬/원격 환경을 동기화할 수 있다. RLS(데이터 접근 권한) 정책도 같은 파일에 기록되므로 보안 규칙이 코드처럼 버전 관리된다.

**끝나면 보이는 것**
- `supabase/` 폴더 아래 `config.toml` 파일과 `migrations/` 하위폴더 생성
- `npx supabase db push` 명령으로 마이그레이션이 원격 DB에 반영됨
- npm 스크립트에서 `npm run db:push` 로 쉽게 실행 가능
- `supabase/README.md` 에 db push/rollback 절차 및 주의사항 기록

**주의**  
T-005에서 생성한 `src/lib/supabase.ts` 의 클라이언트가 먼저 완성되어야 이 작업이 의미가 있다. 이번 작업에서 생성하는 마이그레이션 파일은 비어있는 상태로만 push되며, 실제 테이블과 RLS 정책은 T-007 이후 작업에서 추가한다.
