## 목표
단일 사용자용 이메일 로그인을 붙이고 비로그인 접근을 막는다.

## 배경 / 요구사항 참조
- NFR-004 접근 제한(1.2 강화): Vercel 공개 URL. anon key 만으로는 누구나 읽고 쓸 수 있으므로 로그인 + RLS 를 1단계와 동시 적용.
- 계정 1개, 회원가입 UI 없음(대시보드에서 생성).
- 원본: 요구사항.md v1.2 (2026-10-11 개정). 아래 단계·조건은 v1.2 기준.

## 작업 단계
1. LoginView: 이메일 + 비밀번호(또는 매직링크) 로그인, 로그아웃 버튼
2. 세션 store: onAuthStateChange 로 현재 사용자 유지
3. 라우터 가드: 비로그인 → /login, 로그인 → 홈
4. 회원가입 화면·링크 없음

## 완료 조건
- [x] 비로그인 상태에서 모든 보호 라우트가 /login 으로 이동
- [x] 로그인 후 새로고침해도 세션 유지 (persistSession 명시, 테스트는 getSession 복원 경로)
- [x] 로그아웃 후 보호 라우트 접근 불가 (가드 + App.vue watch 테스트)

## 결정 / 주의 사항
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**: 로그인 화면을 만들고, 로그인하지 않은 사람이 앱의 다른 화면에 들어가지 못하게 막는 작업입니다.

**왜 필요한가**: T-002와 T-005에서 라우터와 Supabase 클라이언트가 준비되었지만, 아직 누구나 모든 화면에 접근할 수 있습니다. 이 작업으로 개인의 운동 데이터가 보호되고, 로그인한 사용자만 자신의 데이터를 볼 수 있게 됩니다.

**끝나면 보이는 것**:
- 앱을 열었을 때 로그인 화면이 먼저 나타남
- 이메일과 비밀번호를 입력해 로그인 가능
- 로그인 후 페이지를 새로고침해도 로그인 상태 유지
- 로그인 후 HOME, WORKOUT 등의 화면 접근 가능

**주의**:
- T-005(Supabase 클라이언트)가 완료되어야 하므로 먼저 끝내야 함
- 라우터 가드는 T-002의 라우터 설정에 추가하는 작업이므로 두 작업의 경계를 명확히 할 것
- 30분 안에 끝내려면 메일 인증이나 비밀번호 재설정 같은 고급 기능은 추가하지 말 것
