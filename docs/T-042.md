## 목표
일일 체중 대신 평균·추세를 계산한다.

## 배경 / 요구사항 참조
- **FR-009**: 체중 기록: 날짜, 체중, 측정 시간, 메모. 표시는 7일 평균·30일 평균·장기 추세 우선.

## 작업 단계
1. `src/lib/date.ts`: KST 날짜 키(kstDateKey), addDays, diffDays, todayKst — 다른 lib 와 공용
2. `src/lib/body/weightTrend.ts`: toDailyLatest(날짜별 최신 1건), rollingAverage(7일, 측정 3개 미만이면 null), weightTrend(30일: 양 끝 7일 평균 우선, 분포가 기간 1/3 미만이면 insufficient)
3. 결측일은 분모에 넣지 않는다(실제 입력값만). 해석 문구(지방 증감 등)는 내지 않고 숫자만
4. Vitest: KST 경계, 하루 N행, 최소 건수, 기간 밖 제외, 추세 4케이스

## 완료 조건
- [x] 테스트 5개 이상 통과 (weightTrend 9 + date 4)
- [x] 데이터 3일뿐이어도 에러 없음 (3건이면 평균 산출, 2건이면 null 로 숨김)

## 결정 / 주의 사항
- 30일 추세의 "측정 분포가 기간의 1/3 미만이면 insufficient" 는 요구사항에 없는 구현 상수(ROLLING_MIN_COUNT 와 함께 상단에 둠). 데이터가 쌓인 뒤 조정.
- 추세는 숫자(startValue/endValue/deltaKg)만 돌려준다. 화면 문구는 "함께 나타난 패턴" 수준으로(FR-014, 7.4).
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**  
여러 번의 체중 측정값으로부터 7일 평균, 30일 추세를 계산하는 순수 함수를 만든다.

**왜 필요한가**  
하루의 체중 변동은 수분/음식/배변 등으로 크게 흔들린다. 사용자가 실제 성장·퇴보 추세를 정확히 인식하려면 7일 평균으로 추세를 보여줘야 한다. 또한 30일 기준 상승/하강/유지 방향을 표시하면 장기 성과를 명확히 할 수 있다.

**끝나면 보이는 것**
- src/lib/weight.ts: movingAverage(logs, days), trend(logs, days) → 'up'|'down'|'flat' 두 함수
- src/lib/__tests__/weight.test.ts: 경계 케이스 테스트 5개 이상 (데이터 1/3/7/30일, 결측 등)
- 데이터가 3일뿐이어도 에러 없이 실행, 30분 내 완료

**주의**  
T-016(body_metrics 테이블)에서 정의한 대로 **날짜별 최신 측정 1건**만 사용한다. 예를 들어 2026-10-12에 3번 측정했으면 마지막 측정값만 취한다. 결측일(측정 기록 없는 날)은 0으로 채우지 않고 행을 제거하므로, 계산 중 "데이터가 없다"는 경우를 처리해야 한다.
