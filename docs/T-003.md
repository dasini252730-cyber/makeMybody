## 목표
코드 품질 hook이 쓸 lint/typecheck/build 스크립트를 확정한다.

## 배경 / 요구사항 참조
- **TECH**: 기술: Vue 3 + Vite / Supabase(PostgreSQL, Auth, RLS, Storage, Edge Functions) / Vercel / AI는 추후 연동.

## 작업 단계
1. eslint(flat config) + eslint-plugin-vue + typescript-eslint + prettier 설치
2. `npm run lint`, `npm run typecheck`(vue-tsc --noEmit), `npm run build` 스크립트 정의
3. `.editorconfig`, `.prettierrc` 추가
4. 전체 lint 통과 확인

- [x] npm run lint 가 에러 0
- [x] npm run typecheck 통과

## 결정 / 주의 사항
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**: 코드를 자동으로 검사(ESLint)하고 정렬(Prettier)하며 타입 검사(vue-tsc)하는 도구를 설정합니다.

**왜 필요한가**: 팀원들이 같은 코드 스타일을 유지하고, 버그를 미리 발견하며, 커밋 전에 코드 품질을 확보할 수 있게 합니다. hook 시스템이 이 스크립트를 사용하므로 설정이 필수입니다.

**끝나면 보이는 것**:
- `npm run lint` 실행 시 Vue/TypeScript 코드 스타일 문제를 찾고 자동 수정
- `npm run typecheck` 실행 시 TypeScript 타입 오류 검사(vue-tsc 사용)
- `npm run build` 전에 자동으로 lint/typecheck 통과 확인(hook 실행)

**주의**:
- T-001이 완료되어야 package.json과 tsconfig.json 파일이 존재합니다.
- eslint flat config는 v9+ 최신 형식입니다. 공식 문서 참고: https://eslint.org/docs/latest/use/configure
- prettier와 eslint 규칙 충돌을 피하기 위해 `eslint-config-prettier` 설치 필수.
- 30분 안에 끝내려면 npm 캐시가 따뜻해야 합니다(dependencies 다운로드 시간).
