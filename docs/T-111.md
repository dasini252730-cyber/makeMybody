## 목표
NumberStepper 에 label 과 ariaLabel 이 둘 다 비면 이름 없는 spinbutton 이 된다. 타입으로 택일을 강제하거나 DEV 경고를 넣고, BaseButton/BaseCard/BaseTextField 에 라벨·포커스 링·대비(NFR-006)를 점검한다. T-009 3차 리뷰 사소 항목.

## 배경 / 요구사항 참조
요구사항.md의 NFR-006 섹션을 참조한다.

## 작업 단계
1. **NumberStepper 라벨 필수 체크**: label과 ariaLabel이 모두 비면 개발 경고 또는 TypeScript 오류 처리. props 검증으로 "둘 중 하나는 필수"를 명시.
2. **BaseButton 포커스 스타일**: `:focus-visible` 또는 `:focus` 상태에서 outline이나 box-shadow로 명확한 포커스 링 표시 (대비 충족).
3. **BaseCard·BaseTextField·ToastHost 검증**: 의미론적 마크업, aria 속성, 키보드 포커스 흐름 확인 (이미 구현된 경우 참고 표시).
4. **ToastHost aria-live 변경**: `aria-live="polite"` → `aria-live="assertive"` 로 변경해 긴급 알림이 스크린 리더에 즉시 통보.
5. **키보드 수동 테스트**: Tab/Shift+Tab로 포커스 이동, Space/Enter로 버튼 활성화, 숫자 입력은 화살표 키 또는 직접 타이핑 등이 작동하는지 확인.

## 쉬운 설명

**한 줄 요약**: 앱 기본 부품(버튼, 카드, 입력창, 숫자 조절기, 알림)이 화면 읽기 프로그램과 키보드로도 제대로 작동하도록 정리하는 작업입니다.

**왜 필요한가**: T-009에서 만든 UI 부품들이 시각적으로는 좋지만, 접근성 표준(WCAG)을 완전히 따르려면 작은 문제들을 해결해야 합니다. 특히 숫자를 입력하는 NumberStepper가 라벨 없이 만들어지는 것을 막아야 하고, 알림(Toast)이 스크린 리더 사용자에게 즉시 읽혀야 합니다.

**끝나면 보이는 것**:
- NumberStepper: label과 ariaLabel 중 하나는 반드시 있어야 하는 타입 체크 또는 개발자 경고
- BaseButton: Tab 키로 포커스 이동 시 링(테두리)이 보임
- BaseCard, BaseTextField, ToastHost: 키보드만 쓰고도 모든 기능 조작 가능
- 스크린 리더에서 토스트 알림이 즉시(assertive) 읽혀짐

**주의**: 
- 선행 작업 T-009에서 이미 만든 파일들을 수정하므로, 기존 동작을 깨뜨리지 않아야 합니다.
- T-009의 작업 기록에서 "assertive 전환은 T-111으로 이관"되었으므로, ToastHost의 aria-live 값 변경이 핵심입니다.
- 모든 수정 후 키보드 전용 사용자가 실제로 조작 가능한지(포커스 표시, Tab/Space/Enter 반응) 수동 테스트해야 합니다.
