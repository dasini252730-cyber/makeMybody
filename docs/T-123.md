## 결정 / 주의 사항
- 계산 계층(T-049/T-065/T-108)은 exercise_sets 를 직접 읽지 않고 이 뷰만 읽는다(tech-stack 규칙에 추가 예정).
- 미분류(unclassified) 동작의 볼륨은 보조 머신일 수도 있으므로 호출자(T-108)가 unclassified 로 걸러 "미분류 제외" 를 따로 표시한다.
- volume_kg 포함 범위(보정 154000): (미분류 또는 weight 타입) & basis ≠ assisted_minus & weight_kg > 0 & reps 있음. 그 외 NULL = 계산 불가(호출자가 "일부 세트 제외" 표시). `unclassified` 로 "미분류라 제외" 와 "값 누락" 을 구분. added 의 맨몸 0 은 볼륨 NULL(0×반복이 최고 세트 볼륨 후보가 되지 않게). success 는 그대로 노출 — PR 후보는 호출자가 success is true 로 거른다.
- 뷰 컬럼 변경은 끝에 추가만(create or replace). 제거·타입 변경은 drop view 가 필요하므로 새 파일에서 명시.
- 프로브는 예산 때문에 rls_probe_views.sql 로 분리(자체 픽스처).
- assisted 는 boolean(NULL → false)로 노출해 그룹 키가 두 개만 되게 한다(T-014 결정).
- 없음

## 쉬운 설명

**한 줄 요약**  
데이터베이스에서 운동 성장 분석에 쓸 데이터만 자동으로 필터링하는 보기(뷰)를 만든다.

**왜 필요한가**  
사용자가 세션을 삭제해도(soft delete) 그 세션의 기록이 가장 무거운 무게(PR)나 운동량(볼륨) 계산에 포함되지 않아야 한다. 뷰를 사용하면 계산 함수 어디에나 "삭제된 세션 제외" 조건을 매번 써야 한다는 실수를 구조적으로 방지할 수 있다. 또한 RLS 정책이 자동으로 적용되어 다른 사용자의 데이터는 절대 보이지 않는다.

**끝나면 보이는 것**
- PostgreSQL 뷰 `mybody.v_working_sets` 생성됨
- 삭제된 세션의 세트가 뷰 조회에서 제외됨 (프로브로 검증)
- 다른 사용자의 세트가 뷰에 보이지 않음 (RLS 적용)

**주의**  
선행 작업 T-014(exercise_sets 테이블)이 반드시 완료되어야 한다. 뷰는 읽기 전용이므로 세트를 추가/수정하려면 exercise_sets 테이블에 직접 쓴다.
