## 결정 / 주의 사항
- id 는 클라이언트 UUID(upsert). 세션 하나에 활동 N건 가능(예: 걷기+등산 혼합). 전부 빈 행은 거부, 메모만 있는 행은 허용.
- activity_type 은 walk/hike/run/cycle/other 고정, 생략 시 other(151000) — 빠른 메모 저장이 유형 없이도 들어간다. 세션 유형(PT/strength/mixed/walk/hike/other)과는 별개이며 교차 검증하지 않는다(mixed 세션 허용).
- duration_minutes 상한은 7일(10080분, 151000) — 무박 종주·1박 2일 등산. 세션의 1440 상한과 다름(긴 활동은 활동 기록이 담는다).
- 활동 조회·누적 계산은 세션 deleted_at is null 조인 필수.
- 검증: rls_probe 1번(anon), rls_probe_workout 7c(hike 세션 픽스처, 격리·제약명 단정·upsert·기본 유형·soft delete 제외·cascade 잔존).

## 쉬운 설명

**한 줄 요약**  
걷기나 등산 같은 야외활동을 기록하는 activity_records 테이블을 만들고, RLS로 자신의 활동 기록만 볼 수 있게 보호한다.

**왜 필요한가**  
요구사항 FR-012는 "걷기·등산 기록"이라는 별도의 활동 유형을 정의한다. 세션(workout_sessions)은 주로 실내 운동용이고, 야외 이동(거리·시간·고도 등)은 다른 필드가 필요하다(요구사항 6.2). 또한 다른 사용자가 내 활동을 보지 못하도록 RLS(행 수준 보안)로 접근을 제한해야 한다(NFR-004).

**끝나면 보이는 것**
- Supabase 대시보드에 activity_records 테이블 생성됨
- 로그인한 사용자가 자신의 활동 기록만 조회·수정·삭제 가능
- 다른 사용자나 비로그인 사용자는 활동 기록에 접근 불가
- 세션의 soft delete(deleted_at) 필터링이 작용할 때 활동 기록도 함께 제외

**주의**  
선행 작업 T-013(workout_sessions)이 완료되어야 한다. activity_records가 session_id를 FK로 참조하기 때문이다. 모든 컬럼이 nullable이므로 session_id만으로도 활동 기록을 저장할 수 있다. RLS 패턴은 T-013의 session_items와 동일하게, session을 join하여 소유권을 검사한다.
