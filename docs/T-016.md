## 목표
체중·체성분과 회복 일지 테이블 2개 + RLS(user_id = auth.uid()) + 제약(결측 0 금지, 빈 행 금지, 하루 1행 KST).

## 배경 / 요구사항 참조
- FR-013 체중·체성분(P0.5): 날짜·시각, 측정값, 측정 방식, 메모. 결측일 0 금지.
- FR-014 수면·음주·컨디션(P1): recovery_logs. 6.2 컬럼 정의.
- 원본: 요구사항.md v1.2 (2026-10-11 개정). 아래 단계·조건은 v1.2 기준.

## 작업 단계
1. body_metrics(id, user_id, measured_at timestamptz, weight_kg, body_fat_percent, skeletal_muscle_kg, measurement_method, note, created_at)
2. recovery_logs(id, user_id, log_date, sleep_hours, sleep_quality, alcohol_type, alcohol_amount_note, condition_note, pain_note, created_at)
3. RLS user_id = auth.uid() 각 정책 4개(select/insert/update/delete), 인덱스 (user_id, measured_at desc) / (user_id, log_date desc)

## 결정 / 주의 사항
- body_metrics 는 하루 여러 번 측정 가능(날짜 unique 없음). **집계(7일/30일 평균, 최근값)는 날짜별 최신 측정 1건 기준**으로 계산한다(T-041 저장은 insert, T-042 계산은 일자별 last). 측정 시각 상한은 now()+1시간(기기 시계 오차 허용; T-013 보정 125000 에서 변경, 클라이언트는 measured_at 을 보내지 않는 것을 권장).
- recovery_logs 는 모든 필드를 비우는 update 가 not_empty 로 거부된다 → 비우기는 행 삭제로(T-043/T-044 UI 에 메시지 매핑). recovery_logs 는 (user_id, log_date) 하루 1행 → 저장은 upsert(on conflict). 날짜는 KST 기준(기본값 now() at time zone Asia/Seoul).
- 미입력은 NULL. 체지방률 0 은 결측으로 간주해 DB 가 거부(>0). 메모만 있는 행은 허용, 전부 빈 행은 거부.
- sleep_quality 는 1~5 주관 척도(구현 선택). sleep_hours 0 은 철야(실제 값)로 허용, 미입력은 NULL — 폼 기본값은 비워 둔다. measurement_method 는 자유 텍스트(값 집합 결정은 T-119 needs_decision).
- service_role 권한은 주지 않는다(2차 리뷰). 서버 측 접근은 Edge Function 작업(T-091)에서 테이블 단위로.
- 이미 적용된 마이그레이션은 수정하지 않고 보정 파일(20261012113000)로 바꿨다.

## 쉬운 설명

**한 줄 요약**  
사용자의 체중·체성분과 수면·음주·컨디션 기록을 저장하는 2개 테이블(body_metrics, recovery_logs)을 만든다.

**왜 필요한가**  
운동만으로는 성장을 평가할 수 없다. 체중·체성분 추세(FR-013)와 수면·음주·컨디션(FR-014) 기록을 함께 저장해야 회복 상태 분석이 정확하고, 운동 성과에 영향을 미치는 요인을 파악할 수 있다. 또한 이 데이터는 추후 Fitness Score 계산에 반영될 기반이 된다.

**끝나면 보이는 것**
- Supabase 대시보드에 body_metrics(체중/체지방률/근육량), recovery_logs(수면/음주/컨디션) 두 테이블 생성
- 자신의 기록만 조회/저장 가능, 다른 사용자 기록은 RLS로 접근 차단
- recovery_logs는 user_id+log_date unique 제약으로 하루에 한 번만 저장 가능(수정 가능)
- body_metrics는 measured_at이 타임스탬프이므로 같은 날 내에 여러 번 기록 가능

**주의**  
T-006(마이그레이션 워크플로우)이 완료된 상태에서 진행한다. recovery_logs의 unique 제약은 user_id와 log_date 조합이므로 같은 날짜 재입력 시 update 하거나 에러를 처리해야 한다. body_metrics는 측정 시각이 다르면 같은 날짜에 여러 행 저장이 가능하다.
