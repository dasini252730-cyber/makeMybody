## 목표
DB 타입을 생성하고 타입 헬퍼를 만든다.

## 배경 / 요구사항 참조
- **TECH**: 기술: Vue 3 + Vite / Supabase(PostgreSQL, Auth, RLS, Storage, Edge Functions) / Vercel / AI는 추후 연동.

## 작업 단계
1. `npm run db:types` = `supabase gen types typescript --linked --schema mybody > src/types/supabase.ts` (eslint/prettier 제외 파일)
2. `src/lib/supabase.ts` 의 createClient<Database> 로 연결 — 테이블·뷰 접근이 타입 검사됨
3. `src/lib/__tests__/databaseTypes.test.ts`: 핵심 테이블·컬럼·Insert 필수 id·뷰 노출을 expectTypeOf 로 고정(vue-tsc 빌드가 타입 검사)
4. 스키마가 바뀌는 작업은 마이그레이션 적용 후 `npm run db:types` 를 다시 돌리고 변경분을 같은 커밋에 넣는다(README)

## 완료 조건

- [x] typecheck 에러 0

## 결정 / 주의 사항
- 산출물 경로는 src/types/supabase.ts (원장 제목의 database.ts 는 v1.0 문구). schema 는 mybody 만 생성(public 은 다른 앱 것).
- 생성 파일은 손으로 고치지 않는다. 타입 테스트는 런타임이 아니라 vue-tsc(빌드)에서 검사된다 — vitest 는 --typecheck 없이 expectTypeOf 를 실행만 한다.
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**  
Supabase 데이터베이스 구조를 TypeScript 타입으로 자동 변환해서 코드 작성 중 컴파일 타임에 실수를 잡는다.

**왜 필요한가**  
운동 기록·세션·세트·운동 등 DB 테이블 구조가 코드에 반영되지 않으면 컬럼명이나 타입을 잘못 쓰는 오류가 런타임에야 드러난다(TECH). 자동 생성 타입을 쓰면 IDE에서 자동완성과 컴파일 검사가 가능해져서 개발 속도가 빨라진다.

**끝나면 보이는 것**
- supabase.from('workout_sessions')을 쓸 때 테이블명·컬럼명이 IDE 자동완성으로 제안됨
- npm run typecheck 에러 0 (타입 불일치 사전 감지)
- src/types/supabase.ts (18KB 자동 생성 파일, 스키마 변경 시마다 갱신)

**주의**  
T-021의 RLS 검증이 끝났으므로 테이블 스키마는 확정된 상태다. 선행 작업 완료 직후 한 번 실행하는 단순 작업이므로 5~10분 안에 끝난다. src/lib/supabase.ts는 이미 Database 타입을 import하고 있으므로 타입 생성 후 바로 typecheck가 통과해야 한다.
