## 목표
main/dev 브랜치가 자동 배포되도록 Vercel 을 연결한다.

## 배경 / 요구사항 참조
- **TECH**: 기술: Vue 3 + Vite / Supabase(PostgreSQL, Auth, RLS, Storage, Edge Functions) / Vercel / AI는 추후 연동.

## 작업 단계
1. Vercel 프로젝트 생성, GitHub 저장소 연결
2. 환경변수 VITE_SUPABASE_URL / ANON_KEY 등록
3. SPA fallback 용 `vercel.json` rewrites 추가
4. 프리뷰 배포 URL 에서 로그인 동작 확인

## 완료 조건
- [ ] dev 푸시 시 프리뷰 배포 생성
- [ ] 배포본에서 새로고침해도 404 없음

## 결정 / 주의 사항
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**: 앱을 인터넷에 공개 배포하고, 개발 중 변경사항이 자동으로 반영되도록 Vercel과 GitHub를 연결하는 작업입니다.

**왜 필요한가**: T-001(Vite 프로젝트)과 T-005(Supabase 연결)가 완료되면, 누구나 접속 가능한 URL로 앱을 배포할 수 있어야 합니다. Vercel은 GitHub에 코드를 푸시할 때마다 자동으로 최신 버전을 배포해줍니다.

**끝나면 보이는 것**:
- Vercel 대시보드에서 MY BODY OS 프로젝트 생성 완료
- GitHub에 푸시할 때마다 자동으로 Vercel에서 배포 시작
- 배포된 URL(예: my-body.vercel.app)에서 앱이 동작하고 새로고침해도 404 없음
- 환경변수가 Vercel에 등록되어 배포본에서도 Supabase와 정상 연결됨

**주의**: .env.example의 VITE_SUPABASE_URL과 VITE_SUPABASE_ANON_KEY 환경변수를 Vercel 프로젝트 설정에 등록해야 함. SPA(Single Page App)이므로 vercel.json에 rewrites 설정을 추가해야 하고(새로고침 시 404 방지), 라우터가 필요한데 T-002/T-008이 아직 예정 상태이므로 라우터 동작은 이 작업 이후에 확인 가능.
