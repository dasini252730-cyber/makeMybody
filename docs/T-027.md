## 배경 / 요구사항 참조
- FR-001 세션 생성, FR-005 수정·삭제(soft delete), NFR-003 클라이언트 UUID + upsert.

- 원본: 요구사항.md v1.2 (2026-10-11 개정). 아래 단계·조건은 v1.2 기준.

## 작업 단계
1. useWorkoutRepo: createSession(id = crypto.randomUUID()) 를 upsert 로, getSession, listSessions(기간, deleted 제외), updateSession(updated_at), softDeleteSession
2. raw_note / structured_status / source_type 필드 포함
3. 반환 타입 { ok, data } | { ok:false, error } 로 실패를 숨기지 않음
4. Vitest: supabase 클라이언트 모킹으로 upsert 호출 인자·deleted 필터 검증

## 쉬운 설명

**한 줄 요약**: 운동 세션을 저장하고 불러오는 JavaScript 함수 모음을 만듭니다.

**왜 필요한가**: 운동 기록 앱이 DB에 세션을 정확하게 저장해야 합니다. 같은 세션을 여러 번 전송해도 하나로만 저장되어야 하고(upsert), 저장 성공/실패가 명확해야 합니다. 이를 구현하는 composable이 필요합니다.

**끝나면 보이는 것**:
- 세션 생성/조회/수정/삭제 함수가 있는 `src/composables/useWorkoutSession.ts` 파일
- 함수가 `{ ok: true, data: {...} }` 또는 `{ ok: false, error: "..." }` 형태로 결과를 반환
- Vitest 테스트에서 upsert 호출과 soft delete 필터 동작 검증

**주의**: T-022(타입 생성)가 in_progress 상태이므로 필요한 타입이 이미 있는지 확인 후 시작하세요. T-014(세트 테이블)는 이미 done이므로 참고만 하면 됩니다.
