## 목표
사용자 기본 신체 정보 테이블을 만든다.

## 배경 / 요구사항 참조
- **FR-001**: 사용자 프로필: 성별, 생년월일, 키, 현재 체중, 목표 체중, 운동 경력, 주당 운동 목표. Fitness Score/분석의 기초 데이터.
- **NFR-003**: 개인정보: Supabase RLS로 사용자별 접근 제한.

## 작업 단계
1. 마이그레이션: profiles(user_id PK→auth.users, sex, birth_date, height_cm, weight_kg, target_weight_kg, training_years, weekly_goal, created_at, updated_at)
2. RLS 활성화 + `auth.uid() = user_id` 정책(select/insert/update/delete)
3. auth.users insert 트리거로 profiles 자동 생성
4. db push 후 대시보드에서 정책 확인

## 완료 조건
- [ ] 본인 행만 조회/수정 가능
- [ ] 회원 생성 시 profiles 행 자동 생성

## 결정 / 주의 사항
- 특이사항 없음. 코드 줄수 예산(.claude/code-budget.json)과 RLS 원칙을 지킨다.

## 쉬운 설명

**한 줄 요약**  
사용자의 키, 체중, 목표 체중 같은 기본 신체 정보를 저장하는 데이터베이스 테이블을 만든다.

**왜 필요한가**  
이 정보들은 Fitness Score(체력 점수) 계산과 운동 분석의 기초가 된다. 또한 Supabase RLS(행 기반 접근 제어) 정책으로 사용자는 자신의 데이터만 볼 수 있게 보호되므로, 다른 사용자의 정보는 절대 접근할 수 없다.

**끝나면 보이는 것**
- Supabase 대시보드의 데이터베이스에 profiles 테이블이 생김
- 회원가입하면 자동으로 profiles 행이 생성됨
- 자신의 데이터만 조회/수정 가능, 다른 사용자 데이터는 접근 불가능

**주의**  
T-006(Supabase 초기화)이 완료되어야 이 작업을 시작할 수 있다. 테이블 스키마는 `.claude/rules/tech-stack.md`의 Supabase 규칙을 따라야 한다 (모든 테이블에 user_id 컬럼 + RLS 4개 정책).
