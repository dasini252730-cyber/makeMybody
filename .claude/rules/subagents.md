# 서브에이전트 사용 규칙

두 서브에이전트가 `.claude/agents/` 에 정의되어 있다. Agent 도구의 `subagent_type` 에 이름을 넣어 호출한다.

## backlog-briefer (haiku, 저비용)
- 역할: 작업을 쉬운 말로 설명하고 관련 파일을 찾아 `docs/<id>.md` 의 "쉬운 설명"·"관련 파일" 섹션을 채운다.
- 호출 시점: 작업을 `in_progress` 로 올리기 **직전**, 작업당 1회. 이미 채워져 있으면(플레이스홀더가 없으면) 건너뛴다.
- 프롬프트: `작업 T-xxx 를 브리핑해줘.` 처럼 id 만 준다. 구현 지시를 섞지 않는다.
- 결과 활용: 돌아온 관련 파일 목록을 구현의 출발점으로 쓴다. 목록에 없는 파일을 새로 만들 때는 이유를 작업 기록(`note`)에 남긴다.

## adversarial-reviewer (opus, 고비용)
- 역할: 생성/변경된 파일을 공격적으로 검토하고 REWORK / REVIEW_OK 판정을 낸다. 코드를 고치지 않는다.
- 호출 시점 (둘 다 필수):
  1. 작업 중 파일을 **새로 만들거나 바꾼 뒤** 한 묶음(보통 작업 단계 1~2개)마다 1회. 한 줄 수정마다 부르지 않는다.
  2. `review` 로 올리기 직전 최종 1회 (변경분 전체).
- 프롬프트: `T-xxx 리뷰. 변경 파일: a, b, c` 또는 `T-xxx 리뷰. 변경분 전체`.
- 결과 처리:
  - 치명 → 즉시 수정 후 재호출. 수정 없이 review 로 올리지 않는다.
  - 중요 → review 전에 수정. 수정하지 않기로 했다면 사유를 `note` 로 남긴다.
  - 사소 → done 전까지 처리하거나 후속 작업으로 `add`.
  - 리뷰어와 의견이 다르면 요구사항.md 를 근거로 판단하고, 판단이 안 서면 `needs_decision` 으로 올린다.
- 비용 통제: 같은 파일 묶음에 대해 REVIEW_OK 를 받은 뒤 변경이 없으면 다시 부르지 않는다. 작업당 보통 2~3회.

## 공통
- 서브에이전트는 backlog.json 을 직접 열 수 없다 (hook 동일 적용). CLI 결과를 쓴다.
- 서브에이전트 결과는 사용자에게 보이지 않는다. 핵심(판정, 치명 항목 수, 바뀐 결정)을 보고에 요약한다.
- 그 외 범용 에이전트(Explore, general-purpose 등)는 사용자가 요청할 때만 쓴다.
